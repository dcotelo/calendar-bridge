# Terminal demos

`.tape` files for [VHS](https://github.com/charmbracelet/vhs). Regenerate the
GIFs in `docs/assets/demos/` with:

```bash
make demos
```

## What is and isn't demonstrated

Every demo runs the real binary against a synthetic fixture generated by
`prepare.sh` — fabricated OAuth client documents and tokens in
`/tmp/calendar-bridge-demo`. Nothing here contacts Google and nothing reads
your real `config.yaml` or `secrets/`.

That has one consequence worth stating plainly: **there is no recording of a
successful sync against live calendars.** A real pass needs real OAuth tokens
for two real Google accounts, so recording one would mean either putting live
credentials in a public GIF or fabricating output that the tool never actually
produced. Neither is acceptable, so the demos cover what genuinely runs
offline: the CLI surface, the authorization flow up to the point where it needs
a browser, and the failure path an unauthorized account produces — which is the
first thing most people will actually see.

If you want to record a successful pass for your own use, point `prepare.sh` at
a real config and re-run `make demos`; just don't commit the result.
